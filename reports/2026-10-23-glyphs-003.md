# 2026-10-23 - spec 003, the Nerd Font glyph alphabet

Run on the Hayato, like the two reports before it: the alphabet is a fact about
the fonts installed here and about what `foot` draws with them, and neither can
be answered inside a chroot.

## What was exercised

`specs/003-glyphs.md` - `enum Glyph`, the generated table behind it, the eight
names the symbol package does not draw, the reserved glyph column and the four
witnesses (`check-system.sh`, the manual, `AGENTS.md`, the tests).

## The font and the filter

`fonts-nerd-symbols` is the only symbol font the image guarantees, and it is
DFSG-stripped: Octicons, Codicons, Devicons, Seti and Powerline, and **none** of
Font Awesome or the MDI plane 15. `scripts/make-glyphs.sh` asks fontconfig which
font that family resolves to and what that file draws
(`fc-query --format='%{charset}'`), and filters a hand-written candidate table
against it:

| | |
|---|---|
| font | `/usr/share/fonts/truetype/nerd-fonts-symbols/SymbolsNerdFontMono-Regular.ttf` |
| SHA256 | `9536496476507f7621d05fb6f42dc53cd6e736267329c7b30e2772bab4281740` |
| character map | 24 ranges, 1 511 codepoints |
| Nerd Fonts | 3.5.1 (`glyphnames.json`, `cod-*`/`oct-*`/`seti-*` only) |
| names | 101: **93** draw a codepoint, **8** are text |
| frame + alphabet | 105 codepoints, 12 of them the frame's box-drawing characters |

The eight text names are the ones that would need Font Awesome: `kbd` (keyboard),
`wifi`, `bt` (Bluetooth), `bat` (battery), `pad` (touchpad), `=` (calculator),
`qr` and `crop`. The other 93 are codicons and octicons (`\u{ea85}` terminal,
`\u{ea83}` folder, `\u{f4e5}` image, `\u{eb34}` network, …).

## The codepoints were looked at

A table that parses is not a table that reads. The candidates were rendered from
the installed font with `pango-view --markup` (symbol font at 20 pt, the name and
codepoint beside it in JetBrains Mono) and inspected row by row; four were wrong
on the first pass and were corrected:

- `Theme` was `oct-command_palette` (a play triangle); it is now
  `cod-symbol_color` (`\u{eb5c}`), a painter's palette.
- `Next`/`Prev` were `cod-arrow_right`/`cod-arrow_left`, the same codepoints as
  `ArrowRight`/`ArrowLeft`; they are now the chevrons `\u{eab6}`/`\u{eab5}`.
- `Document` had no candidate (a page with a play badge would have been
  `cod-file_media`); it is `cod-notebook` (`\u{ebaf}`).
- `Disk`/`Database` were both cylinders; `Database` was dropped and `Disk` keeps
  `oct-database` (`\u{f472}`), the closest thing to a drive this set has.

The rendered grid is the evidence for the shapes; the codepoint values are the
generator's comments beside each name, re-checkable against upstream's table.

## foot draws them, and the premise was wrong

The spec's problem statement said foot cannot draw Font Awesome. Measured with a
probe window in the running session (a `foot` with `app-id=glyphtest`, captured
with `grim`): a Codicon (`\u{ea85}`), an Octicon (`\u{f4e5}`), an IEC symbol
(`\u{23fb}`) and a Font Awesome solid codepoint (`\u{f1eb}`, wifi) all render.
`foot.ini(5)` says why - the dynamic fallback list *is* searched - and the
shipped `foot.ini` also names `Symbols Nerd Font Mono`, `Font Awesome 6 Free
Solid` and `Material Design Icons version 6` explicitly (the prompt's glyphs).
The alphabet is Nerd Font for the reason that survives: the row's picture must
come from the one symbol font the package list guarantees and occupy one cell,
not from whichever family answers and at that family's size. That correction is
now in the spec, in `docs/plan-ui.md` §6 and in the manual's symptom page.

## The bug the generator had

`make-glyphs.sh` counted the character map's ranges with `lo[count]` before
`count` existed, and mawk used the empty string as the array key: the *first*
range was written to `lo[""]`, never tested, and `Power` (`\u{23fb}`, the first
range, `23fb-23fe`) came out as a text fallback while every other codepoint was
right. Nothing failed - a table with one name in the wrong state still builds.
It was found by reading the generated `draw: None` list and asking why `power`
was in it. `count` is initialised now, and `tests/glyph_script.rs` runs the
generator against a fixture character map that is missing exactly `U+EA85`, so
the filter has an assertion instead of a reading.

## What the witness answers

`check-system.sh`, framework section, against this branch's binary on the device:

```
OK: the alphabet's font is the one it was generated from (Symbols Nerd Font Mono, Nerd Fonts 3.5.1)
OK: the frame's characters render (no installed font is missing one)
OK: the rows' glyphs render (105 codepoints, every one in Symbols Nerd Font Mono)
OK: 8 names the symbol set does not draw render text, not boxes
```

Four failures were exercised with stub binaries, because a witness that only
passes is a witness nobody has read: a codepoint the font lacks (`does not carry:
face U+1F600`), a stale pin (`the alphabet's pin is for another font`), a
fallback that is not short text, and a pre-003 binary. The union of the installed
character maps first travelled to `awk` as a `-v` argument and died of `ARG_MAX`
- and because `awk` then printed nothing, both "renders" lines passed *vacuously*.
That is why the union goes on stdin now and why an empty one FAILs instead of
answering "nothing is missing".
